# Second Wind 地图原文核验

核验日期：2026-10-23。来源为用户提供的 `magical_athlete_sec_livro_de_regras_da_expansao_s_350133.pdf`，共32页；以下页码按PDF页序从1计数，与相关页面印刷页码一致。本文件记录规则规格与证据边界，不代表所有机制已经实现。

## 企鹅：已经得到明确裁定

PDF第26页 Penguin 的解释明确写道：**“I recover from tripping after my main move.”** 因此企鹅倒地后的下一次主移动以主骰加倍代替跳过，并在这次主移动完成后恢复，不会一直倒地加倍。

第23页的普通绊倒通则与此兼容：绊倒不截断正在进行的移动，能力与其他移动仍可发生。企鹅的例外改变该次主移动的行为与恢复时点，没有把任意技能移动变成恢复。

回归情景：倒地后一次加倍并恢复、下一回合恢复普通骰距、技能移动不恢复、主骰加倍与加法增益分别结算、复制企鹅同样恢复。移动中失去能力与移动中再次绊倒的精确交互须结合主移动任务边界实现，不应直接在回合开始清除倒地。

## Twisty Twirl：地图与首次穿越

PDF第10–11页跨页完整显示地图。以起点为0：上直道1–12，第一弯道12；远端直道13、14；第二弯道15；下直道16–29；终点30。Twist标识位于**13与14之间的边界**，不是一个整格。其余为普通格，没有星星、绊倒或箭头。

第23页规定首名穿过Twist的选手抽取一张Twist卡并执行。实现需要一个本场持久化的一次性触发标记，不能把它写成每次停在第14格触发。普通移动或技能移动都可能穿越；传送不沿路径逐格移动，因此越过该边界的传送不触发，是依据同页warp定义的实现解释。

建议数据接口：`twistBoundary: { before: 13, after: 14 }`。当前引擎 `motion` 一次提交完整目的地，因此需要明确Twist相对原移动的处理时点；原文只说“passes through”，没有给出跨越后剩余步数遇到方向反转时怎样继续的示例。不能把未说明的中途截断策略标作官方裁定。

测试情景：12→13不触发、12→14触发、12→18也只触发一次、后来者穿越不再触发、抽卡后序列化恢复不重复抽卡、同组同时移动只由行动顺序最先的穿越者触发。反向首次穿越与传送跨越应有清晰、公开的项目裁定。

## Whirly World：可确认机制与图片缺口

2026-10-24 更新：已按用户决定开放六组传送的网页版布局，并接入 Dots 的六组模型。3↔5、7↔12、10↔15来自下述图像核对，20↔23由用户补充，18↔22及24↔27来自共同确定的补齐方案；其余格子普通。完整实现验收见[模型接入记录](whirly-world-model.md)，决定与原图证据区分见[来源跟进](whirly-world-source.md)。以下原图缺口仍成立，不再是网页适配的开放阻塞。

第23页规定：停在一个Whirl端点时，传送到另一端；从前端进入向后传送，从后端进入向前传送。越过端点而不停留不触发。Warp不算move，也不触发越过选手的能力；以warp抵达另一格仍属于停在该格。

建议数据接口：`{ kind: 'warp', to: number }`，配对必须对称。在到达任务中记录这次Whirl配对，避免同一条Whirl立刻把选手再送回来；这不应屏蔽旅馆等其他到达能力，也不应阻止后来新的移动再次使用这对端点。

第21页的透视图沿相同的0–30编号可以确认上段三对端点：**3↔5、7↔12、10↔15**。下段部分被前景盒子遮挡，尚未找到足以独立核对全部端点的无遮挡原图，**不可猜测补齐，也不可仅做这三对后声称完整还原Whirly**。

测试情景：每对双向落点传送、越过不触发、技能传送到端点、倒地角色被移动后触发、无越过能力误触发、同一对无无限往返、到达时触发其他角色能力、传送队列刷新恢复。

## 网页实现的明确解释与任务时序

`src/engine/twist-cards.ts`负责13张卡的数据、持久化状态与串行任务；引擎通过依赖回调接入，不另起一套随机源。以下是网页实现为闭合交互所作的解释，区别于前文可以直接从原文确认的事实：

- Twist触发检测是普通移动完成后的起止位置跨越13/14边界，含逆向跨越；整段移动不拆成两次，因此不会重复触发“移动一次”能力。抽卡及其后续任务在原移动的落点能力之前处理；即使原移动跨越终点，Twist也必须在本次冲线终结对局前触发。卡片改变赛向后，按改变后的赛向判定终点。
- 镜像世界只切换赛向，所有棋子的物理位置保持不变；起点变为终点，第一/第二弯道按反向路线解释。该变化不调用warp，不产生传送到达效果。
- 传送带把仍在赛的角色同时送到新赛向的第1格；加3只应用到主移动。已经冲线、淘汰者不回到赛场。
- 占卜池在主移动全部增减完成后按实际步数判定：前进或后退的绝对步数达到6都被淘汰，其他技能移动不受影响。
- 季终决战的“全部分数”解释为本场两档名次奖励之和，决赛冠军独得，亚军为0；资格阶段不发放名次分。角色既有的技能分仍分别结算，不能混入“全部名次分”再重复发放。非决赛角色离开该场，决赛不重新执行赛前能力。Doppelgängster先替代首位冲线，随后才记录资格；已经有首名资格后，不会把第二个资格当成第一名再次替代。Mastermind命中资格赛首名时，沿用原预测优先序取得第二个资格。如果只剩一名选手或一个未淘汰的资格者，按仅剩一名选手的通则直接取得全部名次分，不等待不存在的第二名。
- 季终决战抽出前已有正式完赛名次时，设置`ruleHold.kind='twist-late-finale'`并暂停；抽出的卡留在`drawn`，原有积分、名次和剩余任务保留，尚不创建新资格赛。该情况属于前述未决规则，网页实现没有替原作作出奖励重分配裁定。
- 交换集市按玩家而非角色发一张牌。拥有多角色者可选其中一名在赛角色替换。后端逐个收集私有承诺，全部承诺前不改变任何角色或公开选择；最终统一换牌、保留位置与倒地状态、不执行新卡的赛前能力。被换下与未采用的卡进入公共弃牌堆；原选秀角色仍在玩家的已用名单中，本赛程不能重选。新换上的实物牌通过`twistBorrowedCardId`记录，赛后归公共弃牌；若时间小鬼把该角色保留到下一场，实物牌也保留到那次额外出赛结束后再归还，避免丢牌或重复抽取。资源不足时暂停并保留已抽牌，不能只给前面部分玩家发牌。
- 无Bite Mark时，实验室产生独立中立巨口：它没有玩家控制权、没有名次分，不计入普通选手的领先/落后/最后一名；每回合由该回合玩家为它投骰，所以受到该玩家“固定骰”的替代。有人使用Bite Mark时，复用该选手，其额外移动仍走普通越过和到达能力链。中立巨口到达终点后离场，不得伪造玩家或名次。
- 固定骰设置时每位玩家实际投一次；后续取固定值，不消耗新的随机数。洗牌不属于投骰，继续使用原随机源。诅咒跳席保留已离场席位；如果固定骰只会在失活席位间循环，则暂停、保留待处理任务与现有积分，不补判平局或胜者。
- 时间小鬼保留的是下一场一次性额外角色，不能加入Re-Runner的永久名单。最后一场触发不延长预先锁定的赛程。Mush保留触发时有效能力，其他消耗资源不跨场复制。

必要接入点：创建本场选手后、固定行动序列前调用`prepareRace`；移动事务记录跨越任务；`boardTasks`置于角色落点效果之前；`mainDistance`在后退符号前增加传送带距离、`blocksMain`在真正主移动前检查最终步数；回合结束插入巨口任务、`advance`交由诅咒跳席；`rollFor`查询`fixedDie`；冲线前用`beforeFinish`截获资格、发分使用`placementPoints`，赛后释放使用`raceEnd`。`beforeRaceEnd`处理只剩一个资格者而对手全部被淘汰的情况。第二名决赛资格生成后，旧移动/回合余下任务必须立刻停止，不能让旧任务结束刚开始的决赛。

公开投影只使用`publicState`，它剔除尚未抽取的Twist牌库与交换集市私有承诺。所有暂停、抽牌、等待选择与决赛阶段均保存在JSON状态中，刷新和权威服务器恢复不得重新抽牌。
