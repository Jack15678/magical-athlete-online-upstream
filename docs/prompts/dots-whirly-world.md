## 3. 坐标与尺寸：模型必须对得上现有棋子

以固定提交的 `boardPoint(n, false)` 为准。导出的 GLB 使用 **Y 向上**，单位与 Three.js 一致。`TILE = 2.05`，相邻格中心相距2.05，格面约2.0×2.0。31格已经包含起终点，不是31个普通格外加两个端点。

桌面方向下，第 n 格的中心：

```text
0 <= n <= 12:
  x = (n - 4.5) * 2.05
  z = -1.5 * 2.05
13 <= n <= 15:
  x = (12 - 4.5) * 2.05
  z = (n - 12 - 1.5) * 2.05
16 <= n <= 30:
  x = (27 - n - 4.5) * 2.05
  z = 1.5 * 2.05
所有格子的棋子落脚锚点：y = 0.22
```

几个核对点（Three.js / 导出后 GLB）：

```text
0  = (-9.225, 0.22, -3.075)
12 = (15.375, 0.22, -3.075)
15 = (15.375, 0.22,  3.075)
20 = ( 5.125, 0.22,  3.075)
23 = (-1.025, 0.22,  3.075)
30 = (-15.375,0.22,  3.075)
```

Blender 默认 Z 向上。若使用标准 glTF 的 Y-up 导出转换，将 Three 坐标 `(x,y,z)` 放在 Blender 的 `(x,-z,y)`。最终必须重新导入 GLB 验证锚点，不能只凭 Blender 视图判断轴向正确。

- 根节点名称：`track_whirly_world`。导出后根变换为位置(0,0,0)、旋转(0,0,0)、缩放(1,1,1)，不居中重排棋盘。
- 保留空节点 `space_00` 到 `space_30`，导出后世界坐标与上述锚点一致。
- 格子平面保持在棋子落脚高度附近；底座、格子厚度主要向下做。装饰凸起放在边缘，不能让棋子悬空或陷入表面。
- 手机由程序对整个棋盘做 Y 轴 -90° 旋转，坐标变为 `(-z,y,x)`。只做一个统一模型，不另做一张竖屏布局，也不要在模型内提前旋转一次。
- 起点可以向路线后方延伸以容纳多人，但 `space_00` 不能移动。

## 4. 美术方向与可读性

风格是精致的实体玩具桌游：圆润边缘、哑光塑料、清晰的彩色格子、柔和底座，有体积和雕塑感。参考原图里的彩色漩涡与弯曲连接，以及仓库现有棋子的玩具质感。

希望一眼看出“哪两个格子相连”。每一对用同一种颜色和配套图案，不同对互相区分，并在端点角落标明目的格号，例如第3格写“到5”、第5格写“到3”。格号0–30必须清晰；不要只靠颜色传达配对关系。

传送连接可以做成圆润的彩色管道、软管状弧线或贴近棋盘的立体连接带。由你决定具体造型，但必须满足：

- 连接完整地对应到指定两个格子；连接中途经过其他格子附近不代表那里也是入口。
- 管道主要沿内场或跑道外沿排布，避免遮住格号和棋子。相交时能沿颜色与形状追踪，不要混成一团。
- 端点中央给棋子留出稳定的站立区域，漩涡造型可以围绕棋子或嵌在格面中。不能用贯穿格面的深洞让棋子看起来悬空。
- 不要把连接做成可行走桥梁或额外岔路。普通移动仍沿0到30，传送才跳过中间格子。
- 近景要有质感，总览和手机390×844时仍能识别各对。装饰不必多，先保证路线、编号和配对清楚。
- 底座、31个格子、起终点标识、四组传送构成一套完整棋盘。不要把参考图的盒子、骰子、角色插画或水印烘焙进模型。

## 5. Blender 结构与浏览器导出

必须交付真正可编辑的 `.blend`。格子、底座和每对传送分别组织，至少保留这四个组／对象名：

```text
portal_pair_03_05
portal_pair_07_12
portal_pair_10_15
portal_pair_20_23
```

普通格可用链接对象或实例减少编辑量。不要把整张地图雕刻成一个无法独立修改连接的不可编辑网格。最终 GLB 可以合理合并同材质网格，但保留上述四组和全部 space 锚点，便于后续增删连接。

- 导出标准 `.glb`，材质使用能随 glTF 导出的 Principled BSDF/PBR；把 Blender 专用程序纹理按需烘焙，纹理内嵌。不得依赖你电脑的绝对贴图路径。
- 本次不要引入 Draco/KTX2 等额外解码依赖；使用项目现有 GLB 加载方式可直接读取的资源。
- 导出只包含棋盘。灯光、相机、参考棋子可留在 `.blend` 的预览集合，但不放进最终棋盘 GLB。
- 优先用几何和少量材质表现造型，避免高细分、每格独占多张大纹理及大量透明材质。建议目标：约6万三角面以内、8种材质以内、GLB约5MB以内；这些是便于网页使用的目标，不是已经测出的性能结论。若更大，报告实际数据和原因。
- 不要求额外的动画或另一套低配模型。静态模型在低画质下也应清楚；运行时传送动画由现有游戏处理。
